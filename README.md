# よりみち — 地域の魅力発見アプリ

旅の予定がない日にも、景色や地域の食・動植物との出会いから「ここに行きたい」と感じられる、インスピレーション型の小さな試作です。

画面上部に **「※現在サンプルモードで動作中です」** と表示します。モック画像・動画とスポットデータを使い、認証情報や外部サービスのアカウントなしで動作します。

## 起動方法

### Windows のワンクリック起動

プロジェクトフォルダーの `start.bat` をダブルクリックします。Python と Node.js がインストール済みであれば、必要な依存関係を準備し、API とフロントエンドを起動します。初回は依存関係のダウンロードにインターネット接続が必要です。利用中は開いたサーバー画面を閉じないでください。

### ターミナルから起動

Python 3.12 以降、Node.js 24 と npm が必要です。API とフロントエンドをそれぞれ別の PowerShell で起動してください。

#### 1. FastAPI

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

#### 2. React + Vite

```powershell
cd frontend
npm ci
npm run dev
```

ブラウザーで http://localhost:5173 を開きます。Vite が `/api` のリクエストをローカルの FastAPI に転送します。

## 機能

- 日本各地のサンプル写真・動画を縦に見て回るフィード。
- スポットに「行きたい」を付けると、スポット ID がブラウザーの `localStorage` に保存され、マイマップと一覧に反映されます。保存を解除するとマップからも外れます。
- マップのピンや保存済みの一覧を選ぶと、その場所の紹介・ローカルフード・動植物を見返せます。
- マイマップでは北海道・東北・関東・中部・関西・中国/四国・九州/沖縄のカードで、エリアごとの保存数を見て絞り込めます。地図タイルではなく、日本の地域区分を用いた簡易表示です。
- 旅行プラン画面では、マイマップに保存されたスポットをチェックボックスで複数選択し、すべて選択・選択解除できます。選択したスポット ID だけを `POST /api/routes` に送り、日別タイムラインとOSRMによる車ルートを作成します。
- マイマップの「今回のスポットを選ぶ」からも、表示中の保存スポットを複数選択してルートを作成できます。地域で絞り込んでいる場合は、その地域内の候補をまとめて選択できます。
- 1エリア内の保存スポットが3件以上になるとフィードとマイマップにルート提案カードを表示します。カードから進むと、そのエリアの保存スポットだけを使ったプランを自動生成します。
- 保存状態は同じブラウザーで再読み込みしても保持されます。
- フィードのカテゴリーでスポットを絞り込めます。
- 「旅行プラン」から、チェックした保存スポットだけを使った日別タイムラインを作れます。日ごとのスポット分けはサンプルの直線距離ルールを使い、同じ日の訪問順・道路経路・距離・移動時間はOSRMで提案します。選択や保存スポットを変更すると、提案済みのプランは破棄されます。
- フィードに地域の豆知識トーストと世界遺産の特集カード、月別「季節の行事」カレンダーを追加しました。イベントの「行きたい」は、関連スポットをマイマップに保存します。
- イベントから旅行プランを作ると、開催時期を表示し、イベント関連スポットの近くにあるサンプルスポット（世界遺産・豆知識）をルート候補に加えます。
- 「思い出」ではサンプル旅行の時系列ルートを写真とともに振り返れます。旅行したスポットを「行った」として、ウィッシュリストとは別にブラウザーへ保存できます。
- 写真ピンの位置・撮影時刻は `GET /api/memories` のサンプルEXIF風データです。端末写真のアップロード、カメラロール参照、実際のEXIF解析は実装していません。
- 「モデルコース」タブでは共有コースの順路を番号付きで参照し、各スポットの名前・説明・地域の食や動植物・世界遺産表示を確認できます。各スポットのボタンから気になる場所だけを「行きたいリスト」に追加できます。一括追加やチェックボックスによる選択機能はありません。
- モデルコースはサンプルサーバーのプロセス内メモリーに保存されます。外部SNS、アカウント間同期、永続データベースは未接続のため、APIサーバー再起動後は投稿がリセットされます。

## サンプルモードと外部サービス

- `/api/spots` と `/api/spots/{spot_id}` はスポットカタログを返します。探索用の `discovery_categories` と都道府県を使う検索・おすすめロジックは `backend/app/services/discovery.py` に集約し、HTTP APIクライアントは `backend/app/integrations/` と分離しています。現在の候補ソースは試作用カタログで、将来のWikipedia/Wikidata等の外部ソースは、座標やライセンスを検証してから同じSpot形式に変換して追加する構成です。
- スポット・イベント・思い出・モデルコースの画面表示は、引き続き `frontend/public/sample-media/` 内のローカルSVG素材を使用します。別途 `GET /api/spots/{spot_id}/media` からPixabay・Pexelsを検索できますが、現時点ではフロントエンド表示には接続していません。APIキーが未設定、検索結果がない、または両サービスが利用できない場合もローカル素材URLを返します。
- 外部メディア検索を有効にする場合は、バックエンドのプロセス環境変数 `PIXABAY_API_KEY`、`PEXELS_API_KEY` のうち利用するキーを設定してください。両方設定すると非同期に並列検索し、片方の障害時は他方の結果を利用します。キーはレスポンスに含めません。検索結果は同一検索条件でプロセス内キャッシュされ、Pixabayのみの正常結果は24時間、Pexelsを含む正常結果は1時間、空結果・一部障害・ローカルフォールバックは5分キャッシュします。複数プロセス／サーバー間ではキャッシュを共有しません。
- Windowsでは `backend\.env.example` を `backend\.env` にコピーし、`PIXABAY_API_KEY` の `=` の後に取得したキーを設定してください。`start.bat` で起動し直すと読み込まれます。`.env` はGitの追跡対象外です。キーをチャットやソースコードに貼らず、公開リポジトリにコミットしないでください。既に起動中のAPIサーバーには反映されないため、変更後はAPIサーバーを再起動してください。既存の環境変数が設定されている場合は、`.env` より環境変数が優先されます。
- 外部サービスの素材は提供元ごとの規約・帰属・利用可能範囲に従ってください。結果には出典名と元ページURLを含めています。素材を画面に表示する機能を追加する際は、出典表示と各APIの利用条件・再配布制限を確認してください。
- カタログの `data_status` は `sample`（未確認のサンプル）または `sourced`（出典が付いた情報を含む）を表し、`sources` には出典ページ、確認対象フィールド、ライセンス情報（確認できた場合）を格納します。`sourced` はレコード全項目が検証済みという意味ではありません。現在、屋久島の地理・世界遺産に関する説明にはWikipedia出典を、祇園祭の7月17日・24日の神幸祭／還幸祭にはKyoto Travelの公式案内を付けています。写真・いいね数・動植物や食の情報など、出典を付けていない項目はサンプルのままです。Wikipedia本文はCC BY-SA 4.0の表示と記事リンクを付け、画像等は個別にライセンスを確認してください。
- マイマップには地図タイルの接続状態とスポット座標のデータ状態を分けて表示します。OpenStreetMapの著作権表示とODbLライセンスへのリンクを地図の近くに表示し、Leafletの地図上の帰属表示も維持します。
- スポットの `local_trivia`、`is_world_heritage`、`heritage_name` は `backend/app/sample_data.py` のデモデータです。月別のイベントは `backend/app/event_sample_data.py` に分け、各イベントを保存可能なスポット ID に結び付けています。
- `GET /api/memories` は `backend/app/memory_sample_data.py` の旅行履歴、経路座標、写真URL、撮影時刻、緯度経度を返します。写真は試作用モックで、アップロードやEXIF解析は行いません。訪問済みIDは `yorimichi-visited` として `localStorage` に保持され、行きたいID (`yorimichi-wishlist`) とは独立しています。
- `GET /api/model-courses` は `backend/app/model_course_sample_data.py` の香川・愛媛サンプルコースと、サーバー起動後に公開されたコースを返します。`POST /api/model-courses` は既知のスポット ID のみでモデルコースを公開し、プロセス内メモリーに保持します。発見画面にはコース内スポットの順路を表示し、各スポットを個別にウィッシュリストへ追加できます。
- `POST /api/routes` は `event_id` を受け取ると開催目安を提案に加え、イベント地点から直線距離140km以内の世界遺産・豆知識スポットを追加候補にします。候補抽出はサンプルデータによるもので、開催状況・営業時間や旅行全体の実行可能性は検証しません。
- 行事の開催時期、見頃、説明・画像と豆知識は UI 動作確認用のモックです。開催の有無や日程は年ごとに異なります。実際に訪問する前に主催者等の公式情報を確認してください。
- フロントエンドのエリア対応と自動提案しきい値は `frontend/src/regions.ts` に定義しています。3件のしきい値は UI のスマート提案用で、バックエンドはリクエストされたスポットだけから独立して日別プランを計算します。サンプルには関西エリアのスポットを3件含めているため、提案を実際に試せます。
- `POST /api/routes` は、ブラウザーに保存されたスポット ID を `backend/app/services/routes.py` で日ごとの候補に分け、その後 `backend/app/integrations/osrm.py` からOSRM Trip APIへ問い合わせます。OSRMが同日内の訪問順を提案し、道路経路・距離・所要時間と地図表示用のLineStringを返します。
- 日ごとの候補分けは `backend/app/route_sample_data.py` の直線距離140km以内・最大3か所というサンプルルールです。スポット滞在時間は90分の仮定です。OSRMの道路経路は自動車移動の目安で、交通状況や通行規制、公共交通、フェリーの運航、日をまたぐ移動、スポットの営業時間は考慮しません。ルート検索が利用できない場合はサンプル値に黙って置き換えず、APIエラーを返します。
- OSRMの公開デモサーバーは無保証の共有サービスです。過度な利用を避け、必要に応じて `OSRM_BASE_URL` で適切なOSRMインスタンスを指定してください。Nominatimとは別に `OSRM_USER_AGENT` でアプリを識別できます。地図タイルとともにOpenStreetMap contributorsの帰属表示を保ってください。
- 風景カードはローカルSVGのサンプル画像を、穏やかなモーション付きで表示します。動きを減らすOS設定ではアニメーションを停止します。実写動画や外部SNS素材は取得しません。
- マイマップはReact-LeafletでOpenStreetMapのタイルとサンプルスポット座標を表示します。地図にはOpenStreetMap contributorsの帰属表示があり、地域カードは保存数の確認・地域絞り込み用です。ナビゲーションや道路経路案内は提供しません。
- OpenStreetMap標準タイルは共有サービスであり、無制限利用やSLAは保証されません。表示帰属を維持し、タイル利用ポリシーに従ってください。大量利用が必要になった場合は、適切なタイル提供元またはセルフホストを検討してください。
- マイマップの地名検索はFastAPI経由でNominatimを呼び出します。日本国内検索のみ・手動送信・最大5件とし、サーバープロセス内で同一検索を1時間キャッシュして、外部リクエスト間隔を最低1秒空けます。利用者数や複数サーバー構成が増えた場合、このプロセス内制御だけでは公開インスタンスの利用条件を守れる保証がないため、セルフホストまたは別サービスを検討してください。
- フィード、マイマップの豆知識、世界遺産カードでは、利用者が概要欄を開いたときだけ日本語Wikipedia APIを呼び出します。概要はサーバープロセス内で検索語ごとに24時間キャッシュされ、リクエスト間隔は最低1秒です。デプロイ時は `WIKIPEDIA_USER_AGENT` にアプリを識別できる値と運用者の連絡先を設定してください。記事内容はWikipedia contributorsによるもので、画面に記事リンクとCC BY-SA 4.0ライセンスを表示します。再利用時は各記事の著者帰属・ライセンス条件とWikipediaの利用規約を確認してください。
- デプロイ時は `NOMINATIM_USER_AGENT` にアプリを識別できる値と、可能なら運用者への連絡先を含む値を設定してください。検索結果はOpenStreetMap contributorsに帰属し、地図上に一時的に表示されるだけで、行きたいリストには自動保存しません。
- SNS アカウント、SNS投稿API、投稿データベースには接続しません。いいねはこの試作内のウィッシュリストとしてローカルに保存します。
- `/api/status` はサンプルモードと、Google Maps / SNS の `not_implemented` 状態を返します。地図・経路検索以外の表示メディアはローカルのサンプル素材です。

## API とテスト

- `GET /api/health`: 稼働確認
- `GET /api/status`: サンプルモードと未実装連携の状態
- `GET /api/spots`: スポットのサンプルデータ
- `GET /api/discover/spots`: `category`、`region`、`limit`、`random_order=true` で候補を検索・ランダム取得します。カテゴリ・地域の選択肢と、検索件数・データソースも返します。候補自体は現時点ではローカルカタログから取得し、Wikipedia記事を実在座標付きスポットとして見せかけることはしません。
- `GET /api/spots/{spot_id}`: ID を指定したスポット。存在しない ID は 404
- `GET /api/spots/{spot_id}/media?media_type=image&limit=8`: Pixabay・Pexelsの画像または動画検索結果を統合して返します。`media_type` は `image` / `video`、`limit` は1〜30です。未知のスポットは404、不正なパラメーターは422です。プロバイダー別の状態、元ページURL、結果がない場合のローカル素材URLも含みます。
- `GET /api/spots/{spot_id}/knowledge`: 日本語Wikipedia APIから取得したスポットの概要、記事URLを返します。記事が見つからない場合は `null`、未知のスポットは404、Wikipediaの通信・応答エラーは502です。
- `GET /api/geocode?q=京都駅`: Nominatimで日本国内の地名を検索し、最大5件の座標・表示名を返します。2〜120文字の検索語が必要で、上流エラーは502で通知します。
- `GET /api/events`: 開催月・スポット ID を含む行事サンプルデータ
- `GET /api/memories`: 旅行履歴、ルート座標、写真の撮影時刻・位置情報を含むサンプルデータ
- `GET /api/model-courses`: 公開済みモデルコース
- `POST /api/model-courses`: `title`、`description`、`region`、`spot_ids` を受け取り、検証済みコースを共有します。不明なスポットは404、空または重複するIDは422です。
- `POST /api/routes`: `{"spot_ids": ["ine", "fuji-shibazakura"], "event_id": null}` または `{"spot_ids": ["kyoto-kamogawa"], "event_id": "gion-matsuri"}` を受け取り、OSRMの道路経路・距離・所要時間と日別タイムラインを返します。旅行プラン画面またはマイマップで選択したスポット ID のみを送信します。イベント指定時は近隣スポットも候補に加えます。空の ID リストや重複 ID は 422、不明 ID / イベントは 404、経路検索の上流エラーは 502 です。
